# 多人协作

只有边界清晰且收益大于沟通成本时才并行。微小单文件改动不要拆给多人。

## 契约先行

前后端并行前确定：

- 路由和方法；
- 请求字段、类型、默认值和校验；
- 响应DTO、分页和错误行为；
- 权限、数据范围和审计；
- 每个选项和字段的数据Owner；
- 加载、空、失败、只读和边界验收；
- 兼容和回退。

契约Owner负责变更，其他人员不得自行改名、猜字段或增加临时硬编码兜底。

## 建议分工

| 角色 | 责任 |
| --- | --- |
| 产品/契约 | 用户流程、验收、模块影响、DTO、集成决策 |
| 后端 | 模块API、application、权限和测试 |
| 前端 | 页面、交互、全状态、响应式和数据源复用 |
| 验证 | 独立执行运行、浏览器、权限和回归验收 |

避免可写路径重叠。先集成契约，再集成实现，最后对组合结果执行完整证据等级。验证人员不能只复述开发人员的完成结论。
