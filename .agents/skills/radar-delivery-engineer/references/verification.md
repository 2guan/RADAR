# 验证证据

## 证据等级

| 等级 | 能证明 | 不能证明 |
| --- | --- | --- |
| 静态检查 | 规则和结构符合要求 | 代码可运行 |
| 自动化测试 | 已覆盖场景行为正确 | 浏览器可打开 |
| 构建 | 前端可生成生产产物 | 服务能正确提供资源 |
| 运行验证 | 健康接口、SPA入口和资源可达 | 用户流程正确 |
| 浏览器验收 | 指定角色和路径真实可用 | 未测试角色和边界也正确 |

不得把不同等级合并成一句“验证完成”。

## 浏览器验收记录

记录：

- 服务地址与路由；
- 角色，不暴露账号口令；
- 桌面和相关移动视口；
- 具体操作步骤；
- 页面可观察结果；
- 关键接口状态；
- 控制台错误结果；
- 刷新、返回和状态保留结果；
- 加载、空、错误、权限、长文本、边界和重复操作结果。

仅使用本地或脱敏测试数据，不连接生产，不展示Token、真实附件和敏感截图。

## 失败规则

- 构建失败：不得声明运行完成。
- 健康、入口或资源失败：不得声明页面可达。
- 白屏、控制台异常、接口失败、越权、遮挡或溢出：不得声明浏览器验收完成。
- 保存后列表和详情不一致、刷新丢失、重复提交产生重复数据：视为功能失败。
- 跳过检查：最终报告必须说明原因和剩余风险。

在 `npm run build --prefix web` 后执行 `node scripts/verify-app-runtime.mjs`。该脚本使用临时SQLite目录，不得读取生产或现有业务数据。
