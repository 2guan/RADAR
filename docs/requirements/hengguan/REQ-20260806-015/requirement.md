# [hengguan/REQ-20260806-015] 列表列宽边界、筛选有效性与配置动态对齐

## 0. AI 执行约束

- 仅修复共享列表列宽拖拽、现有业务页面已呈现的筛选项及其对应查询；不新增业务字段、页面、权限或数据写入口。
- 优先复用 `DataTable`、`ResizableTitle`、`FilterPanel` 和各模块既有筛选契约；不复制表格或筛选实现。
- 需求、任务范围及影响分析均已完成且为 `ready`；筛选审计发现的缺陷只在本需求允许路径内修复。

## 1. 目标与业务价值

- 要解决的问题：拖拽表格列宽会产生不符合组件约束的宽度并报错；版本概览的申请投产点、任务阶段和任务状态筛选不生效，其他页面的现有筛选项也未完成端到端有效性核验。
- 预期结果：所有采用公共可拖拽表头的列宽始终以 50 至 800 的整数提交；所有已展示筛选项均能生成与前后端契约一致的查询，筛选结果、总数和导出范围一致。
- 业务价值：避免高频列表操作中断，确保用户能可靠缩小工作项范围和导出当前结果。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 有列表查看权限的业务人员 | 需要调整表格阅读宽度 | 进入任一使用公共表格的桌面列表 | 拖动列头右侧手柄 | 列宽实时变化、保存成功且不报错 |
| 有版本概览查看权限的业务人员 | 需要定位投产窗口内工作项 | 打开版本概览并加载筛选选项 | 选择申请投产点、任务阶段或任务状态，可组合使用 | 卡片、总数和导出仅保留匹配工作项 |

## 3. 范围

### 本次要做

1. 在共享可拖拽表头与持久化前统一规范列宽为 50–800 的整数，并覆盖无初始宽度、拖至边界外和已保存非法历史宽度。
2. 清点所有业务页面的 `FilterPanel`、`DataTable` 与自定义筛选，逐项核对前端字段/值、请求负载、服务端解析和结果/分页/导出语义；修复发现的本需求范围内不一致。
3. 以输入项配置中的“是否筛选”作为动态控制：配置开启则对应页面以原有匹配控件出现并有效，关闭后不出现；管理员调整后刷新页面按新配置生效。
4. 修复版本概览的申请投产点、任务阶段、任务状态筛选，并使列表与导出共用同一筛选解释。
5. 为公共列宽边界、版本概览三项筛选、输入项配置动态开关和全页面筛选契约审计增加可定位回归测试，完成桌面与移动端浏览器验收。

### 明确不做

1. 不新增、删除或修改业务输入项、交付件、流程状态、数据库 schema、角色权限、审计事件或对外接口。
2. 不更改筛选项的业务口径；仅让现有可见筛选按其已声明口径生效。
3. 不改变已经支持多内容/多值筛选的字段控件、值形状或组合语义。

## 4. 行为与业务规则

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 用户拖动公共表格或过程配置表的列宽 | 每次传递、显示和保存的宽度均为 `[50, 800]` 内的整数；下限和上限均可达到 | 将小数四舍五入并钳制到最近边界，不向表格组件或偏好 API 提交非法值 |
| BR-002 | 读取历史个人列宽偏好 | 非数字、小于 50 或大于 800 的值不得用于渲染 | 忽略或规范为合法宽度，不阻塞列表加载 |
| BR-003 | 任一页面提交可见筛选项 | 前端字段名、值形状、操作符与服务端筛选契约一致；组合条件取交集，筛选变更回到第一页 | 无匹配项显示“筛选无结果”并可重置；请求失败保留已选条件并提供既有错误反馈 |
| BR-004 | 版本概览按申请投产点、阶段或任务状态筛选/导出 | 列表和导出对相同筛选负载返回同一工作项集合；申请投产点按工作项关联的申请投产点匹配，阶段/状态按当前生命周期节点匹配 | 不匹配记录不展示、不导出；不把问题记录伪装为满足需求/工单专属筛选 |
| BR-005 | 管理员保存输入项配置的“是否筛选” | 页面读取当前配置后仅渲染 `filterable=true` 的对应字段；动态字段沿用其既有控件和值形状 | 关闭时移除该筛选条件并不得传递旧值；配置缺失或字段无筛选契约时不渲染且不影响其他筛选 |

## 8. 研发上下文

- 目标模块 / Owner / 基准分支：`governance` / `hengguan` / `origin/main`；登记主模块为治理模块，因为公共共享 UI 的变更需要统一审计。实施分支为 `hengguan/REQ-20260806-015-table-filter-validity`。
- 多模块协作：`shared/contracts`（前端公共 `DataTable`/`ResizableTitle`/`FilterPanel`）、`identity-access`（个人列表偏好列宽校验）、`settings`（既有输入项配置读取与筛选能力）与 `overview`（只读聚合筛选及导出）是直接改动模块；全体业务前端模块按输入项配置动态生成筛选项并作为回归对象，若审计发现必须修改其私有筛选适配器则在本需求允许路径内修复。Owner 均为 hengguan，合并前需其复核；不得直接访问其他模块私有后端实现。
- 允许与禁止修改路径：见 `ai-task-scope.yaml`。
- 必须复用的能力与公开契约：`DataTable`、`ResizableTitle`、`FilterPanel`、各模块既有 API、`overview/index.js` 已登记聚合契约和现有权限检查。
- 接口契约：不新增 URI 或写 DTO；保持 `/overview/list`、`/overview/export` 的 `{ code, data, message }` 响应和已有筛选负载兼容，列表/导出使用同一字段语义。
- 数据库迁移、历史数据、SQLite/TDSQL/MySQL 8 兼容及回退：无 schema 或迁移变更。回退应用代码即可；个人偏好中已规范的合法宽度不影响旧版本，未删除任何历史数据。
- 必须执行的构建、单元、API、权限、外网白名单与回归测试：覆盖 AC-001/002 的共享列宽单元测试，AC-003/004 的 overview API/导出测试，AC-005 的页面筛选契约审计与命中用例，以及 AC-007 的“是否筛选”开关/刷新/旧条件清除与多内容筛选回归；执行服务器测试、UI 数据源/模块边界/治理检查、前端构建、隔离运行和脱敏管理员桌面/移动浏览器验收。
- 风险、审批与未决问题：风险为 important，原因是共享 UI 影响所有列表、概览跨模块只读聚合和导出一致性。无未决业务规则；筛选审计只修复已呈现筛选的失效契约，不扩大页面功能。
