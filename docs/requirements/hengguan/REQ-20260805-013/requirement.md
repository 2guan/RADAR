# [hengguan/REQ-20260805-013] 统一业务导入模板与导出字段

## 0. AI 执行约束

- 只调整既有 Excel 导入模板、导出列定义、受控值导入解析和相关测试；不新增业务字段、状态或页面入口，不改动未列模块。
- 复用 `settings/process-configuration` 的字段/交付件公开读取能力和既有导入导出、RBAC、审计能力；平台 `import-export` 仅新增向后兼容的模板示例行配置参数和列级日期/时间格式化，不承载业务列规则；不得访问生产数据或写入 `docs/reports/`。
- 受控字段继续遵循 `hengguan/REQ-20260803-009`：业务数据保存稳定属性值，导入兼容属性值或显示值，业务导出使用显示值；系统设置的属性值和显示值均须分别导入、导出。

## 1. 目标与业务价值

- 要解决的问题：各模块模板和导出列与系统设置中的实际可见输入项、交付件不一致；模板缺少可直接照填的示例；受控值列的导入导出口径不统一。
- 预期结果：用户下载任一模板即可看到完整、可填的字段与 1–2 行脱敏示例；导出列按模块口径完整且日期/时间一致；属性值/显示值的输入与显示行为明确。
- 业务价值：降低批量导入失败和二次补录，保证数据交换可读、可追溯且与页面配置一致。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 业务导入操作人 | 新建或批量维护工作项 | 具有模块导入权限 | 下载版本概览、需求、工单、开发、测试、投产申请/审批模板后填报上传 | 模板覆盖全部可见字段，示例可直接参考，受控值可填属性值或显示值 |
| 业务查看人 | 需要批量核对数据或附件 | 具有模块导出权限 | 导出对应模块清单 | 文件含约定状态、全部可见字段和交付件文件名，显示值可读 |
| 系统/人员管理员 | 维护人员或系统设置参考数据 | 具有设置或人员导入导出权限 | 下载、导入、导出人员和各设置对象 | 模板/导出覆盖对象全部字段；属性值和显示值均作为独立列保留 |

## 3. 范围

### 本次要做

1. 复检并修正版本概览、需求分析、工单分析、开发管理、测试管理、投产管理（投产申请、投产审批）的导入模板：每份模板包含其所属配置范围所有 `visible=true` 的可导入输入项，并提供 1–2 行脱敏示例；多选/数组字段的示例必须展示英文逗号分隔的多个值。附件/交付件文件不支持 Excel 批量导入，模板不展示文件名列。
2. 复检并修正人员管理、系统设置各对象的导入模板：每份模板包含对象全部字段并提供 1–2 行脱敏示例；设置对象中属性值与显示值均为独立列。
3. 复检并修正导出：版本概览含“任务状态”、所有可见输入项和交付件文件名；需求、工单、开发、测试、投产审批含“任务状态”、所有可见输入项和交付件文件名；投产申请含所有可见输入项和交付件文件名；人员和系统设置含对象全部字段。
4. 统一日期导出为 `YYYY-MM-DD`（如 `2026-05-05`），时间导出为 `YYYY-MM-DD HH:mm`（如 `2026-05-05 18:46`）；受控字段的业务导出一律使用显示值，导入兼容属性值/显示值；系统设置属性值/显示值一律同时导入、导出。
5. 补齐模块级导入导出单元/API 回归，验证模板列、示例行、可见性过滤、交付件文件名、状态、受控值兼容和日期格式。
6. 统一由 `settings/process-configuration` 动态生成可见内置字段、扩展字段和交付件文件名列；新增、隐藏、删除或改名后，无需改业务模块手写列定义即可同步模板/导出。版本概览聚合各阶段的动态 schema。
7. 结构化组件导出统一保持一个单元格：影响性分析、测试覆盖性分析、投产申请交付制品均按记录换行；投产审批会签按“角色 / 签署人 / 结论 / 时间”每角色一行；版本概览导出关联制品情况，不重复导出投产申请制品明细。附件不支持 Excel 批量导入。
8. 需求、工单的“申请投产点”是由投产申请关联派生的只读结果，不能在导入中伪造投产申请；须从模板移除，导出继续输出真实关联。投产申请 Excel 以一个“交付制品”单元格承载多组制品，每行一组“制品类型 / 交付单元 / 新版本号 / 摆渡状态”，同时兼容旧版四列导入。
9. 可见内置字段的列标题、可见性和示例须随过程配置更新；版本概览也须按各阶段可见性筛选其内置列。人员、投产点和角色导出补齐非敏感的可管理字段；密码哈希、登录失败计数、锁定时间等安全字段继续禁止导出或导入。

### 明确不做

1. 不新增、删除或重排系统设置的输入项、交付件、字典、人员、系统和投产点定义。
2. 不修改业务对象持久化字段、数据库 schema、状态机、权限矩阵或附件存储；不导出附件内容、路径或敏感元数据，仅导出约定的文件名。
3. 不修改问题管理、影响性分析、测试覆盖分析及未列出的设置/业务功能。

## 4. 行为与业务规则

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 下载业务模块模板 | 模板列由该模块当前可见的可导入输入项生成；隐藏输入项不得出现，附件/交付件文件名列不得出现 | 配置读取失败时拒绝生成，返回明确错误 |
| BR-002 | 下载人员/设置模板 | 模板列包含该对象全部可导入字段；设置对象的属性值、显示值各有独立列 | 缺少必需列定义时拒绝生成，返回明确错误 |
| BR-003 | 下载任一模板 | 至少含 1 行、至多 2 行脱敏示例；可多选/数组列在至少一行显示两个以英文逗号分隔的值 | 示例不能通过校验时由自动化测试失败，禁止发布 |
| BR-004 | 导出版本概览 | 含任务状态、其全部可见输入项和交付件文件名 | 无权限或查询失败沿用既有 `401/403`/错误包装 |
| BR-005 | 导出需求、工单、开发、测试、投产审批 | 含任务状态、模块全部可见输入项和交付件文件名 | 同 BR-004 |
| BR-006 | 导出投产申请 | 含模块全部可见输入项和交付件文件名；不额外伪造投产审批任务状态 | 同 BR-004 |
| BR-007 | 导出人员或系统设置 | 含该对象全部字段；系统设置的属性值和显示值均输出 | 同 BR-004 |
| BR-008 | 业务导入或导出受控字段 | 导入接受稳定属性值或唯一显示值并解析为稳定值；导出只输出显示值 | 未知、歧义或非法值拒绝整行并返回字段、原值、原因 |
| BR-009 | 导出日期/时间 | 纯日期为 `YYYY-MM-DD`，含时间字段为 `YYYY-MM-DD HH:mm`，不输出秒、时区或本地化文本 | 空值保持为空，不以当前时间替代 |
| BR-010 | 系统设置导入/导出 | 属性值和显示值均保留；属性值为稳定标识，显示值为用户可读文案 | 缺列、重复稳定值或非法值沿用既有字段级错误 |
| BR-011 | 导出结构化组件 | 每个结构化组件使用一个单元格并以换行区分明细；会签每角色一行，含角色、签署人、结论、签署时间 | 无明细时输出空值或既有明确占位，不拆成不稳定的多列 |
| BR-012 | 导入交付制品 | 需求/工单模板不含派生的申请投产点；投产申请的“交付制品”按换行解析为多组数组，兼容旧四列格式 | 某组格式非法或受控值无效时拒绝整行并返回字段、原值、原因 |
| BR-013 | 修改过程配置 | 内置字段的可见性和标题、扩展字段的可见性和标题在模板和导出中同步生效；模板为新增动态字段生成与字段类型一致的脱敏示例 | 配置读取失败时拒绝生成，返回明确错误 |

## 6. 权限、审计与外网

| 角色 | 查看/新增/修改/动作 | 数据范围 | 内网/外网 |
| --- | --- | --- | --- |
| 已授权业务人员 | 既有模块导入、导出 | 沿用模块数据范围 | 内网 |
| 已授权人员/设置管理员 | 人员或配置导入、导出 | 沿用既有配置权限 | 内网 |

- 无权限处理：服务端继续执行认证、RBAC、数据范围和实体授权，并返回既有 `401/403` 语义。
- 审计要求：业务导入继续沿用既有写入审计；模板下载与导出维持既有只读行为；不记录或泄露附件路径。
- 外网开放场景、字段、动作、附件限制与禁止项：不涉及。

## 8. 研发上下文

- 目标模块 / Owner / 基准分支：`governance` / `hengguan` / `origin/main`；分支为 `hengguan/REQ-20260805-013-import-export-templates`。
- 多模块协作：直接调整 overview、requirements、tickets、development、testing、release、identity-access 与 settings 的模块内导入导出实现；跨模块字段、交付件和显示值只通过 settings 公开入口读取。直接调整 `platform/import-export` 的通用模板生成器与 Excel 渲染器，仅新增 `templateRows` 及列级 `valueType=date|datetime` 可选参数，供 settings/roles/system/release-point 输出脱敏示例和统一格式，不承载领域字段或数据写入；Owner 均为 hengguan。
- 允许与禁止修改路径：见 `ai-task-scope.yaml`。
- 必须复用的能力与公开契约：`server/src/platform/import-export/index.js`、`server/src/modules/settings/process-configuration/index.js`、`server/src/modules/settings/reference-data/index.js`、既有附件文件名格式化和受控值解析入口。平台公共契约仅扩展 `registerIO` 的可选 `templateRows` 和列级 `valueType`，未传入时仍保持原模板和原值输出。
- 接口契约：不改变 `{ code, data, message }` 包装和既有 URI；模板/导出增加或校准 Excel 列，原有可接受导入列继续兼容。受控业务输入接受属性值/显示值，系统设置属性值/显示值仍为两个显式字段。
- 数据库迁移、历史数据、SQLite/TDSQL/MySQL 8 兼容及回退：无 schema/迁移/历史回填；回退代码即可恢复原模板和导出列。
- 必须执行的构建、单元、API、权限与回归测试：针对 AC-001 至 AC-010 的模板/导出测试、`npm run test:api --prefix server`、`npm run test:rbac --prefix server`、`npm run build --prefix web`、范围/UI 数据源/模块边界/治理检查、隔离运行和本地浏览器验收。
- 风险、审批与未决问题：风险为 important；动态配置会使列集随管理员可见性变化，必须用同一配置快照测试模板/导出。用户已给出各模块列口径，无未决产品规则；Owner 审批人为 hengguan。
