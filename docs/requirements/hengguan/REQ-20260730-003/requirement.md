# [hengguan/REQ-20260730-003] 需求与工单分析新增优先级字段

## 0. AI 执行约束

- 仅为需求分析与工单分析增加同一语义的内置字段 `priority`；不改变现有状态、编号、权限、关联关系或其他业务字段。
- `priority` 的唯一合法值固定为“高”“中”“低”。参数配置、前端下拉和系统设置界面均不得把其他值视为可保存的优先级；前端限制不能替代服务端校验。
- 两个业务模块各自拥有自己的 `priority` 列和写入规则；不得以跨模块表访问、统一业务表或共享写服务实现。
- 需求、任务范围及影响分析所列配置、迁移、权限、审计、测试和回退设计已完成；实施中结论变化时先更新本文档和任务范围。

## 1. 目标与业务价值

- 要解决的问题：需求分析和工单分析目前没有一致、可检索、可统计的优先级字段；系统设置虽提供“列表展示、筛选、仪表盘维度”等输入项开关，但现有内置字段不会完整响应这些开关。
- 预期结果：两个分析对象均可保存“高 / 中 / 低”优先级，新增记录及空值导入默认“中”；默认显示在列表和详情编辑器的“基本信息”分区，并可在系统设置分别调整详情可见、列表展示、筛选和仪表盘维度。
- 业务价值：让使用者可在登记、列表检索和仪表盘分析中使用同一优先级口径，同时保留管理员对各阶段展示与统计入口的配置权。

| --- | --- | --- | --- | --- |

| 工单分析人员 | 新建或编辑工单 | 拥有 `ticket` 新增或修改权限 | 在基本信息中选择优先级，或不选择后提交 | 保存“高 / 中 / 低”；未提供值时保存“中” |

## 3. 范围

### 本次要做

1. 在 `requirement` 与 `ticket` 主表分别新增 `priority` 列，字段默认值和存量补齐值均为“中”。
2. 在需求分析与工单分析的创建、编辑、详情、列表、筛选、导入和导出中接入 `priority`；两个编辑器均以 `StageBuiltinField fieldKey="priority"` 声明实际控件，并将其默认放入“基本信息”分区。
3. 在系统设置输入项配置中分别注册 `requirement.priority` 与 `ticket.priority`：内置、单选、非必填、固定选项“高 / 中 / 低”、详情默认显示、列表默认显示、默认可筛选、默认可作为仪表盘维度；管理员可以在各范围独立调整详情显示、列表展示、筛选和仪表盘维度。
4. 使上述四个输入项配置开关对内置 `priority` 的实际运行时行为生效：详情可见性控制编辑器挂载；列表展示与筛选控制各自列表；仪表盘维度控制对应分析维度是否可选和可用。
5. 补齐新库种子、已有环境幂等配置升级、SQLite 与 TDSQL/MySQL 8 配对迁移、脱敏 mock 和测试。

### 明确不做

1. 不新增其他阶段（开发、测试、投产）的优先级字段，也不以本字段改变任务状态、排期、自动分派或审批顺序。
2. 不允许管理员通过输入项配置或参数配置扩展“高 / 中 / 低”之外的可写优先级值；本需求的可配置范围是展示与使用入口，而非业务枚举。
3. 不调整现有图表、筛选、导入模板或 API 中与 `priority` 无关的字段和语义。
4. 不开放外网接口、附件能力或新的权限动作。

## 4. 行为与业务规则

- 当前行为：`requirement`、`ticket` 均无 `priority` 列、服务端白名单或导入导出列；两个列表没有优先级列和筛选项；系统设置没有此内置字段。现有“列表展示 / 筛选 / 仪表盘维度”元数据仅对扩展字段形成完整运行时效果。
- 变更后行为：两个模块分别持久化 `priority`，所有读取响应、列表、详情和导出返回合法值；优先级配置范围为 `requirement`、`ticket`，默认展示和默认开关按本需求登记，并由运行时消费。
- 失败行为：非法非空值被服务端拒绝且不写库；导入仅失败违规行并回显行号、字段、原值和原因；配置关闭的入口不展示或不接受使用，不影响已持久化数据。

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 创建需求或工单 | 请求缺失 `priority`、传入 `null`、空字符串或仅空白时，服务端写入“中” | 不依赖前端初始值；持久化默认值也必须为“中” |
| BR-002 | 更新需求或工单 | 未传 `priority` 时保留原值；传入 `null`、空字符串或仅空白时规范为“中”；传入合法值时写入该值 | 非法非空值返回 4xx，原记录 `priority` 不变 |
| BR-003 | 创建、更新、导入 | 合法值仅为“高”“中”“低”，服务端校验必须由两个模块共用同一固定枚举规则 | 不得因前端下拉、字典项或配置被改动而接受其他值 |
| BR-004 | Excel 导入 | `priority` 列空缺或空白时按“中”导入；非空非法值拒绝该行 | 结果包含行号、字段 `priority`、原值和“仅支持高、中、低”的原因；其他合法行不受影响 |
| BR-005 | Excel 导出 | 导出模板和导出数据均包含“优先级”列，值为三个合法值之一 | 旧模板未带该列时允许导入并按 BR-004 默认值处理 |
| BR-006 | 初始创建、已有库升级或读取历史行 | 新列为非空且默认“中”；迁移补齐历史 `NULL` 或空白值 | 不能把历史记录显示为空或使详情、列表、仪表盘报错 |
| BR-007 | 详情/编辑器渲染 | 两个编辑器的 `priority` 控件在 `basic` 分区声明并默认可见；管理员关闭“详情页显示”后该控件不再渲染 | 关闭展示不改变已保存值；重新启用后按原值回显 |
| BR-008 | 列表展示与筛选 | 两个列表默认显示“优先级”列；管理员关闭“列表展示”或“作为筛选条件”后，只影响该范围对应入口 | 关闭列表列不影响筛选；关闭筛选不影响列表列；服务端不能因前端隐藏而停止校验 |
| BR-009 | 仪表盘维度 | `dashboard_dimension=true` 时，仪表盘仅在相应统计阶段/对象范围提供“优先级”维度，并以“高/中/低”分组、筛选和钻取；关闭后禁止新增使用该维度的图表 | 已保存且被关闭的图表按既有非法维度兼容策略返回空数据，不得错误统计或扩大到另一范围 |
| BR-010 | 配置升级 | 新库种子登记两个内置字段和固定选项；旧库按 `scope_key + field_key` 补齐缺失定义及默认元数据 | 不覆盖管理员已调整的分区、排序、可见性、列表、筛选、仪表盘或必填配置 |

## 8. 研发上下文

- 目标模块 / Owner / 基准分支：登记主模块为 `governance`（Owner `hengguan`），因为本需求须成对修改平台持久化迁移并协调多模块配置/仪表盘契约；业务字段所有权仍分别属于 `requirements` 与 `tickets`。从最新 `main` 创建分支 `hengguan/REQ-20260730-003-priority-field`。
- 多模块协作：受影响模块为 `requirements`、`tickets`、`settings`、`dashboard`、`platform/persistence` 及 `governance` 文档。直接修改需求/工单仅为其各自字段、路由和页面；直接修改 settings 是注册与消费输入项元数据；直接修改 dashboard 是让原本只支持扩展字段的维度开关支持内置 `priority`；直接修改 platform/persistence 仅为双端配对迁移。所有 Owner 与公开能力复核人为 `hengguan`，合并前须复核兼容性。
- 允许与禁止修改路径：见 `ai-task-scope.yaml`。
