# [hengguan/REQ-20260801-003] 统一列表展示与用户级列偏好

## 0. AI 执行约束

- 本需求只改造现有列表的通用列呈现能力，以及需求分析、工单分析、开发管理、测试管理、投产申请、投产审批六个业务列表的个人列设置；不新增菜单、角色或审批流程。
- 个人偏好必须服务端保存，按当前登录用户与稳定列表标识隔离；不得用浏览器本地存储替代跨设备保存，也不得使管理员默认配置覆盖用户已保存的偏好。
- 复用 `DataTable`、既有认证、RBAC、审计、输入项配置和阶段字段公开入口；跨模块不访问私有实现。

## 1. 目标与业务价值

- 要解决的问题：各列表的标题、列宽、长文本、排序与列能力不一致；用户不能保留自己调整后的列布局，六个高频业务列表也无法临时显示本阶段其他字段。
- 预期结果：所有使用共享列表的桌面表格具备统一表头、对齐、长文本、省略、列宽调整和排序行为；六个重点列表可按用户保存显示字段、顺序和列宽，并可恢复默认。
- 业务价值：提升高频审核与分析场景的信息扫描效率，在不改变管理员配置或其他用户视图的情况下支持个人工作习惯。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 业务人员 | 打开任一业务列表 | 已登录且有列表查看权限 | 浏览、排序、调整列宽 | 统一、可读的列表；刷新后不丢失当前排序外的列宽 |
| 需求/工单/开发/测试/投产人员 | 打开六个重点列表 | 有对应模块查看权限 | 点击操作列表头“操作”文字右侧的设置图标，选择并拖动列 | 仅自己的显示列、顺序、列宽被保存并跨设备恢复 |
| 管理员 | 调整系统设置→输入项配置 | 有设置权限 | 调整字段的“是否列表展示” | 调整后成为未自定义用户的默认基线，不覆盖已自定义用户 |

## 3. 范围

### 本次要做

1. 扩展共享 `DataTable`：表头统一居中；默认列宽可拖拽；对齐、默认宽度、最小宽度、长文本两行截断和是否可隐藏/移动/排序由列元数据统一表达。
2. 所有接入 `DataTable` 的桌面列表：短文本、编号、状态、枚举/下拉字段居中并采用内容驱动的合理宽度；标题、概述、系统、任务名称、变更内容等长文本左对齐、最多两行、省略并可查看全文。操作列固定最右且不可隐藏、移动或排序。
3. 为六个重点列表的操作列表头在“操作”文字右侧加入“列设置”图标：需求分析、工单分析、开发管理、测试管理、投产申请、投产审批。全部本阶段原生字段和已配置的扩展字段均可临时选择为列表列、拖动排序、拖动列宽，并支持恢复默认。
4. 列设置弹窗采用详情页的分区卡片风格：已显示字段区采用每行两列的拖拽卡片；可添加字段区采用每行三列的紧凑选择卡片；窄屏自动收为单列/双列，保留拖拽与勾选可达性。
4. 新增用户级列表偏好数据与受保护接口，保存 `visibleKeys`、`orderedKeys` 和 `widthByKey`；自动保存，重新登录、刷新或换设备后恢复。恢复默认值删除该用户该列表的偏好记录。
5. 各六个列表接口补齐稳定、白名单化的字段排序；不可由 SQL 字段表达的聚合字段使用定义明确的派生排序键。前端只对服务端声明可排序的字段显示排序入口。
6. 同步六阶段输入项配置的 `list_visible` 默认值、默认排序及新库 seed、已有环境幂等配置升级和本地 mock，使下表成为首次使用和恢复默认时的默认列。
7. 清理需求分析、工单分析已废弃的“计划投产点（`release_point_id`）”输入项配置及其状态必填规则；该物理列已由申请投产关联替代，保存时不得再校验它。

| 列表 | 默认列顺序 |
| --- | --- |
| 需求分析 | 任务状态、需求状态、需求编号、需求类型、需求标题、实施机构、主责系统、协同改造系统 |
| 工单分析 | 任务状态、工单状态、工单编号、工单类型、工单标题、实施机构、主责系统、协同改造系统 |
| 开发管理 | 任务状态、开发状态、任务编号、任务名称、关联需求/工单、开发负责人、实施系统、偏差率 |
| 测试管理 | 任务状态、测试状态、任务编号、任务名称、关联需求/工单、测试负责人、实施系统、偏差率 |
| 投产申请 | 评审状态、申请投产点、变更编号、变更系统、实施机构、变更内容、交付制品 |
| 投产审批 | 任务状态、投产状态、评审状态、会签进度、申请投产点、实施机构、变更编号、需求/工单编号、需求/工单标题 |

### 明确不做

1. 不改造移动端卡片的列设置交互；移动端仍按现有卡片信息层级展示。
2. 不改变业务字段值、状态机、数据范围、导入导出字段或管理员配置权限。
3. 不提供用户之间共享列视图、组织级模板或跨列表复制布局。
4. 不改造未使用 `DataTable` 的表单内预览表和系统设置静态配置表的个性化列设置；其表头样式随共享样式统一时不另设偏好。

## 4. 行为与业务规则

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- |
| BR-001 | 渲染共享列表表头 | 表头文字全部居中；业务列默认可拖拽调整宽度。 | 固定操作列不参与宽度/顺序/显隐个性化。 |
| BR-002 | 渲染字段内容 | 下拉、状态、短文本和编号居中；需求/工单标题与概述、任务名称、主责/协同/实施系统、变更系统/内容左对齐。长文本最多两行并提供原文 `title`。 | 空值显示既有 `—`，不得撑破布局。 |
| BR-003 | 用户打开列设置 | 候选项仅为该稳定列表已声明的原生字段、已启用且可列出的扩展字段；操作列不出现。 | 配置加载失败时保留当前默认业务列，提示可重试，不展示空白表格。 |
| BR-004 | 用户保存偏好 | 服务端以认证上下文的用户 ID 和稳定 `list_key` 写入；请求体不接受用户 ID。一次保存覆盖同一用户同一列表的完整布局。 | 未登录返回既有认证错误；非法列表、未知字段、重复字段、非正宽度或不可操作列返回 4xx，原偏好不变。 |
| BR-005 | 用户再次打开列表 | 若存在合法个人偏好，按偏好渲染；缺失、新字段或已下线字段与当前默认目录合并：保留有效已选字段，新增默认字段按默认位置补入。 | 无偏好或偏好失效时使用当前输入项配置生成的默认布局。 |
| BR-006 | 恢复默认值 | 删除当前用户、当前 `list_key` 的偏好记录，立即按当前默认布局显示。 | 删除幂等；不得影响其他用户或其他列表。 |
| BR-007 | 点击列标题 | 可排序字段默认不显示排序图标；首次点击升序，第二次点击降序，第三次恢复默认顺序。仅在字段已排序时显示当前方向图标；请求仅传稳定字段键，服务端使用模块白名单映射排序。展示别名（任务状态、系统名称、申请投产点、会签进度等）必须映射到实际可排序字段或定义明确的聚合排序值。 | 不支持的、聚合但未定义稳定排序的字段不显示排序入口；服务端拒绝未知排序字段。 |
| BR-008 | 管理员调整输入项配置 | `list_visible` 与默认排序决定无个人偏好时的初始列；管理员配置变更不写入或覆盖个人偏好。 | 已软删除或管理员隐藏字段不被版本升级重新启用。 |
| BR-009 | 保存需求或工单 | 已废弃的“计划投产点”不属于需求/工单当前字段目录，也不参与状态必填校验。新库不得生成该配置；已有库升级时软删除其定义并清除规则。 | 其他现存必填字段仍按当前配置校验。 |

## 6. 权限、审计与外网

- 已认证用户仅可读写和删除自己的列偏好；不新增角色权限，服务端不得接受或信任前端用户 ID。
- 新增、更新、删除个人偏好都写入现有统一审计，审计内容仅记录列表标识与动作，不记录完整业务行数据。
- 不涉及附件、外网访问或敏感信息。
