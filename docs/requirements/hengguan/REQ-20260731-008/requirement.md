# [hengguan/REQ-20260731-008] 统一流程输入项与交付件必填规则校验

## 0. AI 执行约束

- 仅修复已登记流程范围中“系统设置 → 输入项/交付件配置”的必填规则与业务详情、保存和状态流转校验不一致的问题；不新增业务字段、流程状态、交付件或依赖。
- 必填规则、字段可见性和四项呈现能力分别保持既有语义。业务模块只能经 `settings/process-configuration` 公开入口消费规则；服务端仍是最终裁决点。
- 仅使用本地 SQLite、种子、Mock 和自动化测试的脱敏数据；不访问生产数据、附件、账号或外网系统。

## 1. 目标与业务价值

- 要解决的问题：管理员修改输入项或交付件的当前状态必填规则后，需求分析、工单分析及其他详情页可能仍显示旧必填标记，或未校验应填字段；扩展字段与交付件也没有统一显示或提交前校验链路。
- 预期结果：所有已登记流程范围均由同一阶段内容 schema 判断当前状态下的必填性。实施机构设为必填时，需求/工单详情保存空值会被前端提示且服务端拒绝；主责系统设为非必填时，详情不再显示必填标记。交付件必填标记、上传/路径录入、删除最后一份凭证和状态流转校验一致。
- 业务价值：管理员可可信地通过系统设置维护必填规则，避免“设置已保存但业务页不生效”造成遗漏或无效配置。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 流程管理员 | 调整输入项或交付件状态规则 | 具有 `settings.edit` | 将字段/交付件在某状态设为必填或取消必填 | 保存后打开的详情刷新规则，标记和实际校验一致 |
| 业务人员 | 新建、编辑或流转流程记录 | 具有对应模块创建/编辑/状态权限 | 填写当前状态下的字段、扩展信息并上传或录入交付件 | 必填缺失有明确提示；填写完整可保存或流转 |
| 业务人员 | 尝试绕过页面校验 | 已登录且具有写权限 | 直接调用创建、更新、扩展值或状态流转接口 | 服务端拒绝当前状态缺失的必填内容，不产生部分错误写入 |

## 3. 范围

### 本次要做

1. 盘点 `requirement`、`ticket`、`dev`、`test.SIT/UAT/NFT/SEC`、`release_apply`、`release` 所有已登记内置字段、扩展字段、业务组件和附件型交付件的必填消费位置，建立“设置规则、详情标记、前端提交、服务端创建/更新/流转/附件删除”矩阵并自动化校验。
2. 将业务详情的内置字段必填标记和 Ant Design 校验统一改为消费当前范围的 `stage-content` schema；废弃独立的旧必填规则缓存作为业务详情事实源。配置保存后，同页及其他标签页刷新后必须重新加载对应范围规则。
3. 为扩展字段和交付件按当前状态显示一致的必填标记和说明；编辑已有记录时，保存扩展值、主记录和状态流转前都执行同一规则，失败保留用户输入并给出字段/交付件名称。
4. 逐入口核查并补齐服务端 `validateStageContent` 的调用与调用时机，覆盖创建、更新、状态流转、扩展值保存和删除最后一份交付件；不得仅依赖浏览器校验。
5. 对新建记录中尚未取得实体 ID 的扩展字段/交付件明确统一交互：先保存主记录并保留当前填写内容，再在同一编辑会话完成扩展/交付件并校验；不允许在无法录入附件的首次保存阶段因附件型交付件规则造成不可恢复死锁。状态流转仍必须在所有当前状态必填内容齐备后执行。
6. 增加需求分析与工单分析的回归用例，明确验证“实施机构设为必填 → 空值不可保存”和“主责系统取消必填 → 不显示星号且可保存”；增加跨范围、扩展字段、交付件、缓存刷新、无权限与 API 绕过测试。

### 明确不做

1. 不改变字段或交付件的可见性、列表、筛选、仪表盘维度、分区布局、状态定义、默认必填规则或管理员已保存配置。
2. 不新增附件类型、模板、业务数据表、迁移或历史数据补录；不修改已有附件、审计记录和业务记录。
3. 不将必填校验扩展到未登记范围、全文检索、固定对象身份、行操作或未配置的虚拟字段。

## 4. 行为与业务规则

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 管理员保存某范围字段/交付件的状态必填规则 | 业务详情、保存与服务端校验均从相同 scope schema 和当前状态读取规则；配置变更事件仅失效该范围缓存 | 保存失败保留配置；业务页下一次刷新或事件后使用新规则 |
| BR-002 | 当前状态下内置字段被设为必填 | 可编辑详情显示必填标记并在保存前校验；只读详情不显示误导性的可编辑标记 | 前端指出字段；伪造 API 或跳过前端时服务端返回当前状态缺失字段 |
| BR-003 | 当前状态下内置字段取消必填 | 不显示必填标记，不生成浏览器必填规则，服务端不以该配置规则拒绝空值 | 其他固有格式、权限和业务校验保持生效 |
| BR-004 | 当前状态下扩展字段或业务组件被设为必填 | 详情显示必填标记；扩展值保存和主记录保存/流转以相同规则校验 | 不保存错误值；保留已输入内容并显示名称 |
| BR-005 | 当前状态下附件型交付件被设为必填 | 交付件区显示必填标记和允许的提交方式；上传、路径提交、删除最后一份凭证和状态流转均按同一规则判定 | 缺失或删除会导致当前状态不合规时拒绝并返回交付件名称 |
| BR-006 | 新建记录尚无实体 ID | 页面明确提示先保存主记录后提交扩展/附件；首次主记录保存不得因尚无承载实体的附件型交付件陷入不可恢复校验失败 | 创建成功后保留编辑会话和未保存扩展值提示；后续保存/流转执行完整规则 |
| BR-007 | 需求或工单详情的实施机构设为初始态必填 | 打开新增或编辑详情并清空实施机构 | 前端不可保存，服务端创建/更新也拒绝空值 |
| BR-008 | 需求或工单详情的主责系统取消初始态必填 | 刷新详情或接收配置更新 | 主责系统不显示必填标记且空值可通过本次配置校验；未改变其他字段规则 |

## 8. 研发上下文

- 目标模块 / Owner / 基准分支：`governance` / `hengguan` / `main@675ba0c`。登记为治理主模块，以覆盖 settings 公开配置能力与各业务模块的规则消费；所有受影响模块 Owner 均为 `hengguan`。
- 多模块协作：`settings` 拥有规则 schema、缓存事件和通用服务；`requirements`、`tickets`、`development`、`testing`、`release` 消费公开能力并在各自写入口调用统一校验；`platform/attachments` 仅沿用既有接口和授权。各模块直接改动仅为既有配置开关的实际生效，合并前需 Owner 复核。
- 允许与禁止修改路径：见 `ai-task-scope.yaml`。
- 必须复用的能力与公开契约：`settings/process-configuration/index.js`、`getStageContentConfig`、`validateStageContent`、`assertDeliverableRemovable`、`StageBuiltinFields`、`StageContentPanel`、`StageSectionLayout`、配置更新事件和各模块既有 API。
- 接口契约：不新增外网 API。既有 stage-content schema、扩展值、业务创建/更新/状态与附件接口保持 `{ code, data, message }`；仅统一其当前状态必填错误语义。
- 数据库迁移、历史数据、SQLite/TDSQL/MySQL 8 兼容及回退：不涉及 schema 或数据改写。回退应用不删除或重写规则、业务数据、附件或审计；如需业务回退，管理员直接在既有流程配置中恢复规则。
- 必须执行的测试：新增矩阵/API/RBAC 回归用例覆盖 BR-001 至 BR-008 和 AC-001 至 AC-008；执行 `npm test --prefix server`、`npm run test:api --prefix server`、`npm run test:rbac --prefix server`、`npm run build --prefix web`、`node scripts/check-ui-data-sources.mjs`、`node scripts/check-module-boundaries.mjs`、`node scripts/check-governance.mjs`、`node scripts/verify-app-runtime.mjs`、`git diff --check`，并使用本地真实浏览器验证需求、工单和一个含交付件范围的桌面/移动路径。
- 风险、审批与未决问题：风险为重要。附件首次新建受实体 ID 约束，按 BR-006 避免不可恢复阻断，状态流转保持服务端完整校验；无影响实现的未决规则。

- 已知风险：浏览器故意提交空表单时，Ant Design 的既有 `validateFields` 拒绝会记录一条无上下文的 `Object` 控制台错误，但字段错误已在页面逐项显示；本需求未改变该通用编辑器错误传播行为。生产发布前应由流程管理员以真实配置复核各状态的字段/交付件规则，并使用无权限账号抽查服务端拒绝语义。
- 发布验证与回退：发布后在需求、工单及含交付件流程中各抽查一次“设为必填”和“取消必填”，确认刷新页面后详情标记、保存/流转和附件删除一致。回退应用不删除或修改规则、业务数据、附件或审计；如需恢复某项业务约束，管理员仅在既有系统设置中恢复该状态规则。
