# [hengguan/REQ-20260731-006] 全流程输入字段与分区配置能力一致性核查与修复

## 0. AI 执行约束

- 仅核查和修复已登记流程范围内的输入字段配置能力；不新增业务字段、不改变业务数据或升级依赖。
- 复用 `settings/process-configuration` 的公开配置能力和各业务页面既有组件；跨模块改动只限于让已有开关在对应入口实际生效。
- 仅使用本地、种子或自动化测试数据；不访问生产数据、附件或外网系统。

## 1. 目标与业务价值

- 要解决的问题：同一输入字段的详情显示、列表显示、列表筛选和仪表盘维度能力可能只在配置页登记，未在业务页面或数据聚合中实际受开关控制。
- 预期结果：对所有已登记流程范围的内置与扩展输入字段逐项建立能力矩阵；适用的开关在需求、工单、开发、测试、投产及仪表盘入口一致生效。
- 业务价值：管理员可以可信地通过“系统设置 → 输入项配置”管理字段呈现与分析能力，避免配置与实际页面不一致。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 流程管理员 | 调整输入项配置 | 具有流程配置权限 | 修改字段的详情显示、列表显示、筛选或仪表盘维度能力 | 相关业务页和仪表盘刷新后按新规则呈现 |
| 业务人员 | 查询、筛选或查看详情 | 具有对应模块查看权限 | 使用受配置启用的列、筛选条件和维度 | 可见字段与配置一致；禁用能力不可使用 |

## 3. 范围

### 本次要做

1. 盘点 `settings/process-configuration` 已登记的所有流程范围、内置字段和扩展字段，并建立“详情、列表、筛选、仪表盘维度”适用性矩阵。
2. 核查各流程字段在详情/编辑 JSX、列表列、服务端筛选和仪表盘动态维度中的实际控制链路；不一致即修复为同一配置事实源。
3. 对不适用的能力记录明确原因：例如对象身份、固定操作列及全文检索不是单一输入字段，交付件不是列表字段或仪表盘维度。
4. 增加覆盖开关关闭、重新开启、扩展字段、内置字段、缓存刷新和服务端筛选的自动化测试，并完成本地浏览器验收。
5. 补齐 `server/scripts/mock-data.js` 中需求分析与工单分析的既有新增字段演示值：OA编号/工单编号、实施机构、需求接收人、工作量及录入人信息；执行本地 Mock 重建后可在列表和详情验证这些字段。
6. 在“系统设置 → 输入项配置 → 分区配置”中按分区预览字段，允许管理员在同一分区内拖拽调整字段顺序，并直接切换字段半行/整行宽度；保存分区配置时原子写入字段 `sort` 与 `column_span`，详情页按该布局展示。
7. 修复需求分析、工单分析详情页字段网格与分区配置预览不一致的问题：半行字段按实际配置同列成对排列；各阶段状态字段作为详情页顶部专用控件，不出现在分区配置字段预览或布局保存集合中。
8. 全量核查所有使用 `StageBuiltinFields` 的详情页，确保每个 `fieldKey` 仅生成一个实际网格槽位；发现重复、空渲染或与顶部专用状态字段相同的声明时修复，并以自动化检查防止回归。

### 明确不做

1. 不新增、删除或迁移业务字段，不更改历史业务数据。
2. 不把固定对象身份、行操作、全文检索等虚拟能力伪装为输入项开关。
3. 不为交付件新增列表、筛选或仪表盘维度；交付件仅核对其详情承载不受字段开关误影响。
4. 不通过本次拖拽变更字段所属分区、字段类型、必填或四项能力开关；跨分区移动仍使用输入项详情中的“布局分区”配置。

| BR-009 | 字段布局保存或预览 | 每个阶段的 `status_field` 由详情页标题栏独立承载，不参与分区布局预览、拖拽、宽度切换或布局保存；同一字段不得有空白重复布局槽位 | 状态配置本身继续保留；半行字段仅由真实字段槽位占列，按配置排序自动成对排列 |
| BR-010 | 渲染详情字段 | 一个 `StageBuiltinFields` 容器内同一 `fieldKey` 仅允许一个实际渲染槽位，目录字段只有具备可渲染目录定义时才生成槽位 | 重复或空渲染声明不占用网格，避免影响后续半行字段换行 |

| 项目 | 适用？ | 结论、标识与验证证据 |

| 服务端字段校验与导入导出 | 是 | 筛选白名单和动态维度必须与配置一致；创建、更新、导入导出字段校验语义不改变。 |
| 公共能力或跨模块契约 | 是 | `settings/process-configuration` 配置读取/失效事件由业务模块与仪表盘通过公开入口消费；保持旧接口和已保存图表兼容。 |
| 数据库与历史数据 | 是 | 不新增表或迁移；管理员保存分区字段顺序时更新既有 `stage_field_definition.sort` 配置数据，不改变业务记录。回退时可在分区配置中恢复排序，或由管理员通过字段详情调整。 |
| 权限、审计、附件、外网 | 是 | 沿用既有流程配置权限、业务查看权限与审计；不新增附件或外网接口。 |

## 8. 研发上下文

- 目标模块 / Owner / 基准分支：`governance` / `hengguan` / `main@7cb17f2`；登记为治理主模块以覆盖需求文档与跨模块配置一致性治理。
- 多模块协作：受影响 `settings`、`requirements`、`tickets`、`development`、`testing`、`release`、`dashboard`；直接修改限于各模块消费配置的既有实现，Owner 均为 `hengguan`。
- 必须复用的能力与公开契约：`settings/process-configuration` 的 schema、列表字段、配置更新订阅及扩展值能力；`DataTable`、`FilterPanel`、`StageBuiltinField`、`StageContentPanel` 和仪表盘维度元数据。
- 接口契约：沿用已登记的 stage-content schema、字段更新及业务列表筛选与 dashboard 维度/图表接口；新增受既有 `settings.edit` 保护的 `PUT /settings/stage-content/:scopeKey/field-layout`，按 `section_id`、完整 `field_ids` 与 `column_spans` 原子提交排序和宽度，不新增外网接口。
- 数据库迁移、历史数据、SQLite/TDSQL/MySQL 8 兼容及回退：不涉及 schema 迁移；分区排序和宽度仅更新已有配置表的 `sort`、`column_span`，不改业务记录。管理员可再次拖拽和切换宽度恢复布局，应用回退不需要业务数据补偿。
- 必须执行的测试：字段矩阵与分区排序自动化测试、`npm test --prefix server`、`npm run test:api --prefix server`、`npm run test:rbac --prefix server`、前端构建、配置/模块边界/运行验证及本地真实浏览器验收。
- 风险、审批与未决问题：风险为重要；关闭已被旧图表引用的维度必须保持只读加载兼容。字段排序会直接影响详情信息层级，因此只允许在所属分区内排序并在保存前保留预览。无未决业务规则。

## 9. 完成记录

- Mock 数据补齐：`server/scripts/mock-data.js` 为 120 条需求和 20 条工单写入 `issue_no`、`implementation_org`、`receiver`、`workload`、`registrar`、`register_time`。实施机构运行时读取种子 `dict:org`，接收人读取启用人员；脚本在事务内校验所有记录非空、机构和人员来源合法、工作量为单行文本且录入时间精确到分钟。
- Mock 验证：已执行 `node --check server/scripts/mock-data.js`、`node scripts/mock-data.js`（本地 SQLite 重建成功）和后置数据库校验（需求 120 条、工单 20 条，字段不合格记录均为 0）；`npm test --prefix server` 通过（31 通过、1 个 opt-in 跳过），本地服务健康接口返回 `status: ok`。
