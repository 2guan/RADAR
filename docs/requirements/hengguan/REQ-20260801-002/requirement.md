# [hengguan/REQ-20260801-002] 以投产申请投产点替代计划投产点

## 0. AI 执行约束

- 仅实施本需求的投产点语义迁移、期望投产时间及其必要的配置、契约、迁移、测试和 mock 数据改造；不改变投产审批流、系统主数据、权限模型或交付件。
- `release_apply_reference` 与投产申请归 release 模块所有。其他模块只能通过 release 的公开 `index.js` 查询投产点关联，禁止直接读取 release 表；需求、工单各自仍独占自身表的写入。
- 用户已明确会清空本地数据库，不保留 `requirement.release_point_id`、`ticket.release_point_id` 或其历史兼容。迁移仍须追加并同时覆盖 SQLite、TDSQL/MySQL 8。

## 1. 目标与业务价值

- 要解决的问题：计划投产点是需求/工单的单值、人工维护字段，与一个工作项可提交多次投产申请的真实关系不一致，导致筛选、列表和审批详情不同步。
- 预期结果：全系统以投产申请的申请投产点作为唯一投产点来源；一个需求/工单可命中其全部申请投产点；没有投产申请时统一显示和筛选为“投产点待定”。
- 业务价值：消除重复维护和单值丢失，确保分析、任务、投产审批与概览的投产点口径一致。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 需求/工单管理人员 | 编辑或查看分析 | 有需求或工单权限 | 填写期望投产时间；在列表按申请投产点筛选 | 不再填写计划投产点；多申请投产点均可命中 |
| 开发/测试管理人员 | 查看任务列表 | 有任务查看权限 | 查看任务，不再看到投产点列 | 列表聚焦任务字段，后台投产点筛选口径仍一致 |
| 投产审批人员 | 打开投产审批详情 | 有投产审批权限 | 查看本次投产申请详情 | 仅看到申请投产点，不回退旧字段 |
| 管理员 | 系统设置→输入项配置 | 有 `settings.edit` | 配置需求/工单的申请投产点列表列和筛选能力 | 可独立控制派生字段是否显示/筛选 |

## 3. 范围

### 本次要做

1. 删除需求、工单分析中的“计划投产点”输入、服务端字段、编号占位符和数据库列；删除所有以该旧列作为筛选、展示、默认值或审批回退来源的逻辑。
2. 以投产申请引用表为唯一关系来源，提供 release 模块的只读公共契约：按工作项取得全部申请投产点、按投产点反查全部工作项。无任何投产申请时，契约返回系统设置中的“投产点待定”。匹配任一申请投产点即命中筛选。
3. 需求、工单列表以派生的“申请投产点”多值字段展示和筛选；在各自输入项配置中注册该稳定键，并允许管理员独立配置列表显示与筛选。默认显示，默认可筛选。
4. 开发管理、测试管理的任务列表及承接候选列表移除投产点列；其已有投产点筛选改用 release 公开契约。
5. 投产审批详情只展示本次的“申请投产点”；版本概览不再展示“计划投产点”，其投产点筛选改为“申请投产点”。看板、导出、移动端卡片和投产文档等所有剩余旧字段使用点同步改为申请投产点或移除。
6. 在需求、工单分析新增 `expected_release_date`（期望投产时间）：日期选择、任意合法日期、默认非必填、默认不在列表、默认不可筛选、默认支持导入导出，并在输入项配置中注册。
7. 追加 SQLite 与 TDSQL/MySQL 8 迁移：删除两张业务表的旧列，新增期望投产时间列；更新新库种子、配置升级和本地 mock，包含多申请投产点与待定场景。

### 明确不做

1. 不保留旧字段或对旧业务库进行数据回填、映射与双写；用户负责在发布前清空目标数据库。
2. 不改变投产申请、审批、会签、任务状态机或申请投产点本身的必填规则。
3. 不将期望投产时间自动同步为投产申请日期，也不以其限制投产申请或审批。

## 6. 权限、审计与外网

- 复用需求、工单、开发、测试、投产审批及设置的既有查看/编辑权限和数据范围；派生查询不得绕过实体授权。
- 期望投产时间写入复用需求/工单现有更新审计；派生投产点不单独写入审计。
- 不涉及附件或外网能力。
