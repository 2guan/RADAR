# [hengguan/REQ-20260730-005] 需求与工单分析补充实施、接收与录入字段

## 0. AI 执行约束

- 仅修改需求分析、工单分析及其已登记的流程配置与迁移；不改变状态流转、编号规则、RBAC、附件或外网能力。
- 所有写入仅经既有需求/工单服务端白名单；人员候选与服务端校验通过 identity-access 新增的公开只读契约完成，不新增跨模块直查或写入。
- 字段的默认展示、筛选、导入导出和配置均以本需求为准；已有管理员的可见性、排序、必填和自定义配置不得被种子升级覆盖。

## 1. 目标与业务价值

- 要解决的问题：需求和工单分析缺少明确的实施机构、接收人、工作量及录入信息，且“关联问题/工单编号”名称不能准确表达 OA 编号来源。
- 预期结果：两类分析记录具备一致的字段存储、输入、详情、列表、筛选、导入导出和系统设置输入项配置能力。
- 业务价值：提高任务归属、接收和工作量追踪的可见性，并让历史录入来源可审计。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 需求/工单管理人员 | 新建或编辑分析记录 | 具有 create/edit 权限 | 选择实施机构与需求接收人、填写工作量 | 三项内容被保存并可回显、查询、导入导出 |
| 分析记录查看人员 | 打开列表或详情 | 具有 view 权限 | 按实施机构等字段筛选并查看录入来源 | 看到默认字段与只读录入人、录入时间 |

## 3. 范围

### 本次要做

1. 将需求/工单的 `issue_no` 全部用户可见名称改为“OA编号/工单编号”，不改历史 API 字段键或历史数据。
2. 为 `requirement` 与 `ticket` 增加 `implementation_org`（实施机构）、`receiver`（需求接收人，单人）和 `workload`（工作量，单行文本）持久化字段；实施机构下拉来源为机构系统设置中的实施机构，即 `dict:org`。
3. 在详情/编辑页将实施机构置于“实施机构及系统”分区、主责系统前；将需求接收人置于相关负责人；将工作量置于基本信息；将现有 `registrar`、`register_time` 以“录入人”“录入时间”只读置于相关负责人末尾。
4. 默认在列表、筛选、详情页和系统设置输入项配置中注册新字段；可写字段支持服务端创建、更新、导入、导出及审计。只读录入字段支持列表、筛选、详情、导出与配置展示，且不得由客户端或导入写入。
5. 需求分析、工单分析的全部已登记输入项，其“列表展示”“作为筛选条件”“作为仪表盘维度”开关分别独立生效：关闭后从相应 UI 入口移除，开启后恢复；配置保存会通知已打开的页面刷新元数据。
5. 提供 SQLite 与 TDSQL/MySQL 8 成对迁移、全新库种子和已有库幂等配置升级；保留既有管理员配置。

### 明确不做

1. 不修改旧字段键 `issue_no`、历史列值、状态流转或历史录入人/录入时间。
2. 不将新增字段设为必填，不改已有需求/工单的必填规则。
3. 不新增外网接口、附件或权限项；仅新增本需求所需的 identity-access 只读人员校验公开契约。

## 4. 行为与业务规则

- 当前行为：`issue_no` 显示为“关联问题/工单编号”；没有实施机构、需求接收人和工作量；已有登记人/登记时间未在详情与输入项配置中显示。
- 变更后行为：新增字段在两类分析记录中采用相同字段键与交互；录入信息在创建时由服务端写入并始终只读。
- 失败行为：实施机构不在机构系统设置的实施机构字典、接收人不是启用人员或导入值非法时，该次写入/该导入行失败并返回字段、原值和原因；客户端不得静默替换默认值。

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 展示/导入导出 `issue_no` | 标签为“OA编号/工单编号”，字段键与存量值保持 `issue_no` | 兼容旧 API，不迁移历史值 |
| BR-002 | 创建、更新或导入实施机构 | 值为空或为机构系统设置 `org` 字典中的启用值 | 非法值拒绝并返回字段原因 |
| BR-003 | 创建、更新或导入需求接收人 | 值为空或为一个启用人员姓名；仅允许单个值 | 非法、多人或停用人员拒绝 |
| BR-004 | 创建、更新或导入工作量 | 值为空或长度不超过 255 的单行文本 | 含换行或超长拒绝 |
| BR-005 | 创建记录 | 服务端写入当前登录人的 `registrar` 与当前日期 `register_time`；更新、导入不得覆盖 | 忽略客户端的录入字段并保持既有值 |
| BR-006 | 已有数据库启动 | 缺少的内置字段和默认配置被补齐；只更新仍使用旧默认文案的标签 | 不覆盖管理员的布局、排序、可见性、必填或自定义定义 |
