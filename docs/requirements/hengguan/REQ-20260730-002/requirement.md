# [hengguan/REQ-20260730-002] 统一输入项与交付件配置目录及旧库升级

## 0. AI 执行约束

- 以 `governance` 为登记主模块；`settings` 为配置能力主责模块，受影响模块为 `requirements`、`tickets`、`development`、`testing`、`release`、`platform/persistence`。仅修改任务范围允许路径。
- 统一配置目录、配置升级、服务端校验与标准字段渲染接入；保留复杂业务控件的模块 JSX 适配器，不把所有表单强行动态化。
- 输入项、交付件、分区和状态规则的升级必须同时支持新库与已有环境，幂等补齐缺失定义，且不覆盖管理员已有配置。
- 需求、任务范围、影响分析、迁移、测试和回退已完成并为 `ready`；实施中结论变化时先更新文档。

## 1. 目标与业务价值

- 解决的问题：字段语义、必填规则、输入项配置、JSX、列表/筛选、导入导出与交付件默认值分散定义；已有环境不会自动补齐新配置。
- 预期结果：提供一个可复用的内置配置目录和独立、可审计的配置升级机制；普通字段由标准渲染器接入，复杂字段继续使用业务适配器；服务端、导入与前端共享枚举/默认值语义。
- 业务价值：新增字段或交付件时可同时覆盖新库、旧库、系统设置、业务页面和接口，降低遗漏与配置漂移。

## 2. 范围

### 本次要做

1. 建立 `settings/process-configuration` 的内置配置目录，定义字段/交付件的稳定键、默认呈现、数据源、枚举/默认值、能力和升级版本。
2. 建立独立配置升级记录与幂等升级服务；旧库按稳定键补齐缺失字段、分区、交付件和状态规则，保留管理员已有覆盖配置与软删除意图。
3. 为 `requirement`、`ticket` 接入统一的优先级枚举、默认值、服务端 create/update/import 校验及配置升级；非法导入行必须报告而非静默改写。
4. 增强 `StageBuiltinFields`：支持标准字段渲染器与业务 JSX 适配器并存；明确未注册的内置字段不会自动渲染。
5. 统一输入项配置的状态可见/必填读取路径，并为现有 `required.fields` 保留兼容迁移。
6. 规范交付件默认定义、状态规则、模板处理器和旧库补齐路径。
7. 更新规约、模板和示例，说明目录、升级、四位置和测试要求。
8. 根据本地界面回归校准需求/工单编辑器中人员选择控件的垂直基线，使其与同一行普通字段的下拉框对齐；保留原有多选与下方标签展示行为。

### 明确不做

1. 不移除现有复杂业务组件、附件权限、审计或模板下载能力。
2. 不允许管理员修改字段的服务端合法值、数据库绑定或安全语义。
3. 不重写已发布迁移，不连接生产系统，不使用生产数据。
4. 不在本次将所有业务编辑器完全改为 JSON/低代码动态表单。

## 3. 行为与规则

| 编号 | 规则 |
| --- | --- |
| BR-001 | 配置目录是内置字段/交付件的代码基线；数据库配置只覆盖管理员可调整的呈现和状态规则。 |
| BR-002 | 每项配置升级按唯一升级 ID 和稳定键幂等执行；仅补齐缺失项，不覆盖管理员调整或软删除。 |
| BR-003 | 标准字段可由目录渲染；复杂字段须通过 `renderer_key` 和业务 JSX 适配器显式渲染。 |
| BR-004 | `priority` 仅允许 `高/中/低`；缺失或空字符串默认 `中`，非法 API/导入值拒绝并报告。 |
| BR-005 | 列表列、筛选、编辑器和系统设置四个位置逐项声明适用性；筛选不适用时记录理由。 |
| BR-006 | 交付件模板版本不可变；新版本追加，已有管理员模板和状态规则不被默认升级覆盖。 |

## 4. 配置与交付影响分析

| 项目 | 适用？ | 结论与验证 |
| --- | --- | --- |
| 输入项配置注册 | 是 | 建立目录、默认定义和旧库幂等升级；以 `scope_key + field_key` 补齐，不覆盖管理员布局、可见性、排序、状态规则或软删除。 |
| 字段四位置生效 | 是 | `priority` 覆盖需求/工单列表列、适用筛选、编辑器 JSX/标准渲染器和系统设置；其他字段按能力声明逐项验证。 |
| 服务端字段校验与导入导出 | 是 | 统一枚举/默认值规范化；API 与导入共用校验，导入错误含行号、字段、原值和原因。 |
| 交付件配置注册 | 是 | 目录统一默认交付件、状态规则、模板处理器与旧库补齐；附件权限/审计沿用平台能力。 |
| 公共能力或跨模块契约 | 是 | `settings` 公开配置目录/解析契约；各业务模块仅经公开入口读取，Owner 需复核。 |
| 数据库与历史数据 | 是 | SQLite/TDSQL/MySQL 8 添加配置升级记录表和等价迁移；不改写历史业务数据。 |
| 权限、审计、附件、外网 | 是 | 配置写入沿用 settings RBAC 与配置修订记录；附件访问仍经附件平台；无外网影响。 |

## 5. 验收标准

| 编号 | Given | When | Then |
| --- | --- | --- |
| AC-001 | 新库 | 初始化配置 | 内置字段/交付件目录生成与默认布局、状态规则一致。 |
| AC-002 | 旧库缺少内置定义且管理员已调整其他配置 | 执行升级 | 仅补齐缺失定义，已有管理员配置与软删除保持不变，并记录升级结果。 |
| AC-003 | 需求/工单提交 `priority` | create/update/import | `高/中/低` 可保存；空值按规则默认；非法值被拒绝且不写入。 |
| AC-004 | 业务编辑器加载目录 | 标准/复杂字段渲染 | 标准字段按配置挂载；复杂字段由适配器正确渲染；没有声明适配器的字段不会伪装为已渲染。 |
| AC-005 | 管理员打开系统设置 | 查看输入项/交付件配置 | 可查看范围、字段/交付件、状态必填、布局和模板版本；更新即时刷新页面缓存。 |
| AC-006 | 列表和导入导出 | 使用启用能力的字段 | 列、筛选、导入、导出与服务端白名单一致，既有接口字段语义不变。 |
| AC-007 | SQLite 与 TDSQL/MySQL 8 | 执行迁移和升级 | 两端结构、升级记录与幂等行为可用。 |
| AC-008 | 需求或工单编辑器的同一行含人员选择器与普通字段 | 渲染窄/宽屏表单 | 人员下拉控件的左边界、右边界和垂直基线与同列普通字段一致；原有多选和下方已选人员展示保持不变，并可在有权限时移除。 |

## 6. 研发上下文

- 主模块：`governance`；受影响模块和 Owner：`settings`、`requirements`、`tickets`、`development`、`testing`、`release`、`platform/persistence` 均为 `hengguan`。
- 分支：`hengguan/REQ-20260730-002-unify-configuration`。
- 公共契约：配置目录/升级/解析由 `settings/process-configuration` 的 `index.js` 与 `contracts/**` 公开；业务模块不直接访问其内部存储。
- 数据库回退：代码回退后保留升级记录和配置定义不破坏既有业务；如需撤销新增默认项，仅在确认无管理员或业务数据依赖后按升级 ID 执行补偿。
- 必测：配置升级单元测试、settings API、requirements/tickets API、导入导出、RBAC、SQLite/TDSQL/MySQL 8 静态兼容、前端构建与配置页回显。
