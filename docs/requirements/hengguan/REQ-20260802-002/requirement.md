# [hengguan/REQ-20260802-002] 交付件在线预览与版本留痕

## 0. AI 执行约束

- 本需求只优化已配置交付件所使用的统一附件能力；不新增交付件定义、不改变流程状态规则、文件上传大小或既有允许扩展名，也不改业务实体的字段与状态机。
- 复用附件平台的实体级授权、上传校验、审计和 `StageContentPanel`；业务模块不得自行读取附件目录或分别实现预览、版本表。
- kkFileView 必须以内部部署的只读预览服务接入；仅允许它从 RADAR 签发的短时文件地址读取指定附件。不得使用 kkFileView 公网演示站或由浏览器提供任意文件 URL。
- 预览能力必须由“系统设置 → 基础配置 → 交付件预览”控制，默认关闭；服务端环境变量只作为首次部署或设置值为空时的回退值。kkFileView 地址不能由业务前端、预览接口参数或交付件数据指定。

## 1. 目标与业务价值

- 要解决的问题：当前交付件可上传多个文件或填写多个路径，但没有在线预览入口；“更新”只能再新增一条附件，无法辨认哪个版本是当前版本，也无法追溯每次上传人员和时间。
- 预期结果：对 Word、Excel、PDF 文件提供内网只读预览；每个交付文件或路径都有独立、连续的版本链，用户可查看当前版本、历史版本、上传人员和上传时间，并可把某一条交付件更新为新版本。
- 业务价值：减少下载后再核对文件的操作，保留交付物演进证据，降低误用旧文件及因删除导致审计链断裂的风险。

## 2. 使用者与场景

| 使用者 | 触发条件 | 前置条件 | 操作场景 | 完成结果 |
| --- | --- | --- | --- | --- |
| 交付件查看人员 | 打开已保存业务记录的交付件区域或版本历史 | 具有该业务实体的查看权限 | 点击当前或未删除历史 Word、Excel、PDF 的“预览/下载” | 在弹窗中打开只读文档或下载指定版本，关闭后仍停留在原记录 |
| 交付件维护人员 | 发现当前文件或路径需修订 | 具有该业务实体的编辑权限 | 选中一个当前文件/路径并点击“上传新版本”或“更新路径” | 生成下一版本，原版本留存且新版本成为当前版本 |
| 审核人员 | 需要核对交付物变更 | 具有该业务实体的查看权限 | 打开某交付项的“版本历史” | 可按版本查看文件/路径、上传人、时间和当前标识 |

## 3. 范围

### 本次要做

1. 在统一附件平台为每个现有附件补充稳定的逻辑交付项标识、版本号、当前版本标识及上传人手机号、姓名快照和上传时间；同一交付件下仍允许存在多个独立文件/路径，每个独立项各自形成版本链。
2. 将“上传新版本”和“更新路径”定义为追加不可变版本：服务端在同一逻辑交付项内自动递增版本号，新版本成为唯一当前版本；版本号不作为页面输入项或上传接口可写字段。原版本保留文件/路径、上传人手机号、姓名快照和上传时间。普通列表默认只展示当前版本，版本历史展示全部版本。
3. 将删除改为删除逻辑交付项的当前可见项（软删除）；不得物理删除已有版本的数据库记录或存储文件。删除后保留审计和版本历史，仅有编辑权限者可执行，并要求二次确认。
4. 以自托管 kkFileView v5.0.1+ 为 Word、Excel、PDF 的统一只读预览服务：支持 `.doc/.docx`、`.xls/.xlsx`、`.pdf`；当前及未删除历史文件版本均可预览/下载，Office 文件以转换后的 PDF 预览，其他允许上传的格式仍仅下载。路径型交付件只展示路径与版本历史，不尝试预览本地/网络路径内容。
5. 在“系统设置 → 基础配置 → 交付件预览”中提供“启用交付件在线预览”开关和“kkFileView 服务地址”输入项；仅有系统设置查看/编辑权限的用户可查看/修改。系统设置值优先于环境回退值，并在保存后立即生效；开关默认关闭，关闭时不展示预览入口。
6. 提供环境配置 `DELIVERABLE_PREVIEW_ENABLED`（布尔值，默认 `false`）、`KKFILEVIEW_BASE_URL`（内部 kkFileView 根地址）与 `KKFILEVIEW_ALLOWED_ORIGINS`（逗号分隔的允许 HTTP(S) Origin）作为系统设置尚未保存或地址为空时的回退及地址白名单；`ATTACHMENT_PREVIEW_SOURCE_BASE_URL` 仅供 kkFileView 回连 RADAR 拉取短签名文件。仅当有效开关为 `true` 且有效地址为经校验的内部 HTTP(S) 地址时启用预览；地址不得包含查询参数、片段或用户信息，必须精确命中部署侧允许 Origin。该清单同时作为浏览器 iframe 的 CSP `frame-src` 白名单。白名单或来源地址缺失时不得启用预览。
7. 新增受实体查看权限保护的预览会话接口：服务端校验附件为未删除的文件版本、校验实体授权并签发短时、仅用于 kkFileView 拉取的文件 URL；浏览器、kkFileView 和附件目录均不得获得无授权的永久下载地址。
8. 在统一 `AttachmentField` 中提供“预览”“上传新版本/更新路径”“版本历史”和现有下载能力；沿用所有已接入 `StageContentPanel` 的需求、工单、开发、测试、投产申请/任务等交付件页面，无需逐模块复制实现。
9. 追加 SQLite 与 TDSQL/MySQL 8 对等迁移，并以历史附件 `id` 生成初始逻辑项和版本 `1`；已有附件的上传人姓名、手机号（如已有）和上传时间保持不变，历史无法补齐手机号时允许为空且显示既有上传人姓名。

### 明确不做

1. 不提供在线编辑、协同编辑、回写保存、模板编辑或病毒扫描；kkFileView 的 Office→PDF 预览转换仅用于展示，不生成可下载的新业务交付件。
2. 不预览路径型交付件、压缩包、图片、PPT、文本及其他非目标格式；这些文件沿用下载行为。
3. 不改变已有交付件配置、必填校验、状态规则、业务记录权限、存储根目录或对外网开放能力。
4. 不在本需求中清理历史附件、重命名物理文件或为缺失的历史上传人补齐手机号。

## 4. 行为与业务规则

| 规则编号 | 触发条件 | 业务规则 | 不满足时处理 |
| --- | --- | --- | --- |
| BR-001 | 查看交付件 | 同一交付件可有多个逻辑交付项；常规列表每项仅展示最新、未删除版本。 | 无当前版本时显示空态。 |
| BR-002 | 上传新版本 | 用户必须从一个当前文件项发起更新；服务端在同一逻辑项内原子创建 `version_no + 1`，记录当前登录人的手机号、姓名快照和时间，旧版本不被覆盖。版本号由服务端生成，客户端不得提交或修改。 | 目标已删除、不是当前版本、无编辑权、客户端提交版本号或并发冲突时返回 4xx，前端刷新列表并提示重试。 |
| BR-003 | 更新路径 | 仅当前路径项可修改；更新路径同样生成新版本，而不是更新旧行。 | 空路径、无编辑权或并发冲突时拒绝，旧版本保持不变。 |
| BR-004 | 删除交付项 | 删除操作只隐藏该逻辑项，且必须保留其所有版本和审计证据；已删除项不能再被预览、下载或更新。 | 无编辑权返回 403；重复删除保持幂等且不泄露历史内容。 |
| BR-005 | 预览文件 | 对未删除且扩展名为 Word/Excel/PDF 的当前或历史文件版本生成 kkFileView 预览地址；预览会话使用一次性或短时签名文件 URL。 | 路径、已删除逻辑项、缺失文件、未支持格式或无查看权不生成预览，返回明确错误或仅显示下载。 |
| BR-006 | 预览授权 | 创建预览会话时须验证当前用户的实体查看权限；kkFileView 拉取文件时须验证由 RADAR 签发的、绑定单一附件版本的短时签名，不能列目录或读取其他附件。kkFileView 拉取不依赖用户 Cookie。 | 签名失效、篡改、过期、附件已删除或用户创建会话时越权，返回 401/403/404，不返回存储物理路径。 |
| BR-007 | 上传人留痕 | 每个版本记录上传时登录人的手机号、姓名快照和时间；历史记录展示姓名、脱敏手机号和时间，账号停用、改名或改手机号均不改写历史。 | 历史数据无手机号时展示原 `uploader` 姓名并标记为历史导入；新上传如账号未维护手机号，记录空值并写部署诊断日志，不阻断上传。 |
| BR-008 | 审计 | 上传首版、上传新版本、更新路径和删除逻辑交付项均写统一审计，包含交付件标识、逻辑项、版本号及操作人；预览只记安全访问日志（若平台已有该能力），不把文件内容写入审计。 | 审计写入失败时受保护写操作失败并保持原版本状态。 |
| BR-009 | 预览配置 | 系统设置 `deliverable.preview.enabled` 与 `deliverable.preview.kkFileViewBaseUrl` 优先；未保存开关时回退 `DELIVERABLE_PREVIEW_ENABLED`，地址为空时回退 `KKFILEVIEW_BASE_URL`。仅当有效开关为 `true` 且有效地址通过服务端内部地址白名单校验时，才显示预览入口并创建预览会话。 | 开关关闭、地址缺失或不合法时隐藏预览入口，预览接口返回明确的“服务未启用”错误；下载和版本管理不受影响。 |
| BR-010 | 系统设置修改 | 仅有 `settings:view` 的用户可在“基础配置 → 交付件预览”查看设置；仅有 `settings:edit` 的用户可保存开关和地址。保存时服务端校验地址并写统一审计，成功后立即更新有效配置。 | 无权限返回 401/403；地址不合法时拒绝保存且保留原有效配置；不得通过该设置指定外网、带用户信息、查询参数或片段的 URL。 |

本次不改变业务状态机；附件项状态为“当前可见 / 历史版本 / 已删除逻辑项”。

## 5A. 配置与交付影响分析

| 项目 | 适用？ | 结论、标识与验证证据 |
| --- | --- | --- |
| 输入项配置注册 | 不适用 | 不新增或改变业务输入项稳定键、布局、必填或状态规则。 |
| 字段四位置生效 | 不适用 | 新增元数据仅属于统一附件平台，不是可配置业务字段；不进入业务列表、筛选或输入项配置。 |
| 交付件配置注册 | 不适用 | 复用所有既有 `deliverable_definition` 和 `StageContentPanel` 交付件区域；不改变交付件定义、模板或状态规则。 |
| 系统设置基础配置 | 适用 | 在 `app_config` 以稳定键 `deliverable.preview.enabled`、`deliverable.preview.kkFileViewBaseUrl` 登记；新库种子和已有环境的幂等升级只补齐缺失键，不覆盖管理员已保存的开关或地址。复用 `settings` 的基础配置页、权限和审计。 |
| 种子与 mock 数据 | 适用 | 在测试及本地演示 mock 中提供脱敏的 Word、Excel、PDF、路径、历史版本和缺失手机号的历史数据；不改变默认交付件配置。 |
| 服务端字段校验与导入导出 | 适用 | 新版本写入仅由附件平台接口产生，服务端校验逻辑项、当前状态、版本并发和文件扩展名；无附件导入/导出入口，本次不新增。 |
| 公共能力或跨模块契约 | 适用 | 在 `platform/attachments` 公开版本查询、更新、预览会话和受签名保护的只读文件读取契约；`web/src/platform/attachments/AttachmentField.jsx` 是统一消费入口。`settings` 仅负责两个 `app_config` 键的受权限写入、展示与审计；附件平台只读这两个白名单键并与运行时回退值组合，不依赖 `settings` 内部实现；业务模块不直接访问附件表或目录。 |
| 数据库与历史数据 | 适用 | 追加 SQLite 与 TDSQL/MySQL 8 迁移；为每条历史附件回填独立逻辑项、版本 1、当前标识，保留既有上传人姓名/时间及已有手机号；以唯一索引保证版本顺序及当前版本约束，并说明双端实现差异。回退应用可读取旧字段，数据保留不删除。 |
| 权限、审计、附件、外网 | 适用 | 上传/更新/删除继续执行实体编辑授权；预览/下载/历史继续执行查看授权；写操作审计版本号和操作人。上传人手机号仅以脱敏形式展示，接口不得向无实体查看权限者返回。kkFileView 为内网自托管服务，非外网 API；预览会话仅向已授权查看者返回一次性预览 URL，文件 URL 使用短期签名、最小范围、精确 `trust.host` 白名单和服务访问限制。 |

## 6. 权限、审计与外网

| 角色 | 查看/新增/修改/动作 | 数据范围 | 内网/外网 |
| --- | --- | --- | --- |
| 具有业务实体查看权限的用户 | 查看当前项、版本历史、下载与受控预览 | 沿用实体 `view` 授权和数据范围 | 内网 |
| 具有业务实体编辑权限的用户 | 上传首版、上传新版本、更新路径、删除逻辑项 | 沿用实体 `edit` 授权和数据范围 | 内网 |

- 无权限处理：接口返回既有 401/403；前端不渲染相应操作，且不返回文件名、历史版本或存储路径。已授权的预览会话响应可返回单次使用的 kkFileView 预览 URL，但不得返回可配置、可复用的服务端地址字段。
- 审计要求：所有影响版本链的写操作写入统一审计；记录逻辑项、旧/新版本、文件名或路径摘要、操作人和时间。预览不得记录文件内容或签名 URL。
- 外网开放场景、字段、动作、附件限制与禁止项：不涉及。kkFileView 必须部署在受控内网，RADAR 与预览服务间仅允许必要文件拉取地址，禁止向公网站点发送附件。
