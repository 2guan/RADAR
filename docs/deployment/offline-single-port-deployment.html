RADAR 离线单端口部署手册

适用于无互联网环境、仅开放 TCP 3510 的服务器。RADAR 通过 Docker Compose 部署；Nginx 统一入口，kkFileView 仅在内部网络提供文件预览。

1. 适用范围与约定

本手册中的 SERVER_IP 是部署服务器的内网 IP 占位符。执行前，统一替换为实际地址；不要把示例中的占位符原样写入配置。

项目本手册约定
客户端入口http://SERVER_IP:3510
对外开放端口仅 3510/tcp
内部服务RADAR 127.0.0.1:3000；kkFileView 127.0.0.1:8012；NginxWebUI 127.0.0.1:8080
离线包radar-image.tar、kkFileView-4.1.0-docker.tar、nginxwebui.tar
容器网络radar-internal；RADAR 与 kkFileView 通过服务名互访
不要开放 3000、8012 或 8080。它们只应绑定到 127.0.0.1 或 Docker 内部网络。NginxWebUI 是管理面，不能从业务入口 :3510 暴露。

3. 部署前准备

  1. 确认基础条件

    在目标服务器执行。Docker Compose 必须是 v2（命令为 docker compose）。若 3510 已被占用，先确认占用方并停止在该端口提供的旧服务。

    docker --version
docker compose version
ss -lntp | grep -E ':(3510|3000|8012|8080)\b' || true
df -h
free -h

  2. 规划目录并传入离线包

    建议将镜像包与持久化数据分离。下面目录名只是建议；创建后需确保运维账户对其具有读写权限。

    mkdir -p /opt/radar-offline/images
mkdir -p /opt/radar-offline/radar/data
mkdir -p /opt/radar-offline/radar/attachments
mkdir -p /opt/radar-offline/nginxwebui

# 将三个 tar 文件上传或拷贝到：
# /opt/radar-offline/images/

  3. 理解配置中的地址

    SERVER_IP 仅用于浏览器可达的同源入口；容器之间不要使用该 IP，也不要使用 host.docker.internal。同一 Docker 网络内统一使用服务名 radar。

4. 导入三个离线镜像

在无互联网环境中只用 docker load -i，不执行 docker pull。本次离线包已确定内含以下标签：ghcr.io/2guan/radar:latest、keking/kkfileview:4.1.0 和 cym1102/nginxwebui:latest，导入后无需再次标记。

cd /opt/radar-offline/images
docker load -i radar-image.tar
docker load -i kkFileView-4.1.0-docker.tar
docker load -i nginxwebui.tar

docker image ls ghcr.io/2guan/radar:latest keking/kkfileview:4.1.0 cym1102/nginxwebui:latest
若最后一条命令没有同时列出三个指定标签，说明导入包与本手册约定不一致；请停止后续部署并确认离线包来源，而不是临时改用未知镜像标签。

5. 使用 Docker Compose 部署 RADAR

先创建 Docker 内部网络。它不是对外端口；其作用是让 kkFileView 使用稳定服务名 radar 请求附件源。

docker network inspect radar-internal >/dev/null 2>&1 || docker network create radar-internal

5.1 创建 /opt/radar-offline/radar/.env

用编辑器新建该文件，粘贴以下内容，并将所有 SERVER_IP 替换为实际内网 IP。此示例使用 SQLite；数据和附件由 Compose 挂载到宿主机目录。

HOST=0.0.0.0
PORT=3000
NODE_ENV=production

# 首次部署必须替换为随机长字符串和强密码；不要保留尖括号内容。
JWT_SECRET=<请生成至少 32 位的随机密钥>
JWT_EXPIRES_IN=12h
ADMIN_PHONE=<首次超级管理员手机号或登录名>
ADMIN_NAME=超级管理员
ADMIN_PASSWORD=<首次超级管理员强密码>

# SQLite 持久化路径（容器内路径）
DB_CLIENT=sqlite
DB_FILE=/app/data/radar.db
ATTACHMENT_DIR=/app/attachments
WEB_DIST=/app/web/dist

# 单一浏览器来源：Nginx 对外入口
CORS_ORIGINS=http://SERVER_IP:3510
CSP_CONNECT_SRC=self
CSP_UPGRADE_INSECURE_REQUESTS=false
HSTS_ENABLED=false
CSRF_HEADER_VALUE=RADAR

# 上传限制；白名单按逗号分隔。可按本单位制度收紧，修改后重启 RADAR。
MAX_FILE_SIZE=52428800
UPLOAD_ALLOWED_EXTENSIONS=.doc,.docx,.xls,.xlsx,.ppt,.pptx,.jpg,.jpeg,.png,.gif,.tif,.tiff,.pdf,.ofd,.txt,.html,.htm,.xml,.json,.properties,.md,.log,.py,.sql,.zip,.rar

# 交付件预览：浏览器走同源反向代理；kkFileView 在内部经 Docker DNS 回源
DELIVERABLE_PREVIEW_ENABLED=true
KKFILEVIEW_BASE_URL=http://SERVER_IP:3510/preview
KKFILEVIEW_ALLOWED_ORIGINS=http://SERVER_IP:3510
ATTACHMENT_PREVIEW_SOURCE_BASE_URL=http://radar:3000
先替换安全占位符再启动：JWT_SECRET、ADMIN_PHONE 与 ADMIN_PASSWORD 不能使用示例文本，也不要提交到代码仓库、聊天记录或共享文档。
三个预览地址不要混用：KKFILEVIEW_BASE_URL 是浏览器入口，必须带 /preview；KKFILEVIEW_ALLOWED_ORIGINS 是浏览器 Origin，不能带路径；ATTACHMENT_PREVIEW_SOURCE_BASE_URL 是 kkFileView 容器内部回源地址，必须是 http://radar:3000。

5.2 创建 /opt/radar-offline/radar/compose.yaml

请使用以下 Compose 文件。127.0.0.1:3000:3000 是关键：RADAR 不直接对内网客户端暴露，只允许宿主机 Nginx 回源。

services:
  radar:
    image: ghcr.io/2guan/radar:latest
    container_name: radar
    restart: unless-stopped
    user: "0:0"
    env_file:
      - .env
    ports:
      - "127.0.0.1:3000:3000"
    volumes:
      - ./data:/app/data
      - ./attachments:/app/attachments
    networks:
      - radar-internal

networks:
  radar-internal:
    external: true
    name: radar-internal

5.3 启动与本机检查

cd /opt/radar-offline/radar
docker compose -f compose.yaml config
docker compose -f compose.yaml up -d
docker compose -f compose.yaml ps
curl -sS http://127.0.0.1:3000/api/health

健康检查应返回 JSON 且 HTTP 状态为 200。若失败，先查看 docker compose -f /opt/radar-offline/radar/compose.yaml logs --tail=200 radar，不要在未备份数据目录时删除容器或卷。

6. 部署 kkFileView（仅本机 8012）

以下命令加入同一个 radar-internal 网络并限制 CPU/内存。kkFileView 默认将 Office 文档转为 PDF 预览，且禁用页面上的 JPG/PDF 切换按钮。

docker run -d \
  --name kkfileview \
  --restart unless-stopped \
  --network radar-internal \
  -p 127.0.0.1:8012:8012 \
  --memory=1g \
  --cpus=1 \
  -e KK_BASE_URL=default \
  -e KK_TRUST_HOST=radar \
  -e KK_NOT_TRUST_HOST=default \
  -e KK_OFFICE_PREVIEW_TYPE=pdf \
  -e KK_OFFICE_PREVIEW_SWITCH_DISABLED=true \
  keking/kkfileview:4.1.0

确认服务与内部回源：

docker ps --filter name=kkfileview
curl -sS -I http://127.0.0.1:8012/
docker exec kkfileview sh -c 'wget -S -O /dev/null http://radar:3000/api/health'
最后一条命令若返回 HTTP/1.1 200 OK，说明 kkFileView 能通过 Docker 网络访问 RADAR。此方式不依赖 DNS，也不依赖对外端口。

7. 启动 NginxWebUI（管理端只监听本机）

NginxWebUI 使用宿主机网络管理 Nginx。管理界面监听 127.0.0.1:8080，因此不会从 3510 访问到它。

docker run -d \
  --name nginxwebui \
  --restart unless-stopped \
  --privileged=true \
  --network host \
  -v /opt/radar-offline/nginxwebui:/home/nginxWebUI \
  -e BOOT_OPTIONS="--server.port=8080 --server.address=127.0.0.1" \
  cym1102/nginxwebui:latest

本机检查：

docker ps --filter name=nginxwebui
curl -sS -I http://127.0.0.1:8080/
管理入口的访问方式：仅在有独立的运维管理通道时，使用 SSH 本地转发 ssh -N -L 8080:127.0.0.1:8080 运维账户@SERVER_IP 后，在本机浏览器打开 http://127.0.0.1:8080。若没有管理网络通道，请在服务器控制台使用本机浏览器或既有受控跳板访问。不要把 8080 转发到 3510。
若当前 NginxWebUI 版本不接受 --server.address

保留 --network host 和 --server.port=8080，再在服务器防火墙中明确拒绝非本机访问 8080，或只在受控管理网开放它。完成后用 ss -lntp | grep :8080 确认监听范围。业务入口仍只允许 3510。

8. 在 NginxWebUI 配置唯一业务入口

登录 NginxWebUI 后，进入“HTTP 参数配置”或“网站管理”（不同版本名称略有不同），新增一个监听 3510 的 server 配置。保存后先执行“测试配置”，通过后再“重载 Nginx”。下方配置已经预留未来 HTTPS 网关的协议自适应能力。

8.0 在全局 HTTP 配置中添加协议推导

将以下 map 放在 Nginx 的 http { ... } 范围（不是 server { ... } 内）。直接访问 3510 时取当前 HTTP 协议；未来外层 Nginx 传入 HTTPS 标记时，自动改为 HTTPS。此配置不需要修改 RADAR 或 kkFileView 环境变量。

map $http_x_forwarded_proto $preview_scheme {
    default $scheme;
    https   https;
}
server {
    listen 3510 default_server;
    server_name _;
    client_max_body_size 100m;

    # 浏览器请求 /preview/... 时，转发给仅绑定本机的 kkFileView。
    # 结尾的 / 会移除 /preview/ 前缀，使 kkFileView 收到 /onlinePreview?...。
    location ^~ /preview/ {
        proxy_pass http://127.0.0.1:8012/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto http;
        proxy_set_header X-Base-Url $preview_scheme://$http_host/preview/;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }

    # 其他请求全部到 RADAR。
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $preview_scheme;
    }
}
不要省略 X-Base-Url，也不要让客户端传入该头。此处由 Nginx 根据当前或可信上游的协议固定覆盖为 $preview_scheme://$http_host/preview/，kkFileView 生成的子资源才能继续走当前浏览器来源。

8.1 从宿主机检查 Nginx

nginx -t
nginx -s reload
curl -sS http://127.0.0.1:3000/api/health
curl -sS -I http://127.0.0.1:8012/
curl -sS http://SERVER_IP:3510/api/health

最后一条应返回 RADAR 健康检查 JSON。若服务器自身无法用 SERVER_IP 回环访问，可改用另一台获授权内网客户端执行。

8.2 未来增加 HTTPS 域名时：无需增加 RADAR 双套配置

当另一台 Nginx（“外层网关”）把 https://PUBLIC_DOMAIN 反向代理到本机 http://SERVER_IP:3510 时，浏览器仍只使用相对路径 /preview/...。第 8 节的 map 会让 kkFileView 自动生成对应协议的子资源地址，因此内网 IP/HTTP 和外网域名/HTTPS 可以同时使用。

内网浏览器 → http://SERVER_IP:3510
外网浏览器 → https://PUBLIC_DOMAIN → 外层 Nginx → http://SERVER_IP:3510
同一内层 Nginx → / 到 RADAR；/preview/ 到 kkFileView

外层 HTTPS Nginx 配置

证书、私钥和 443 只部署在外层网关；RADAR 所在服务器仍只需要对该网关开放 3510。证书文件路径按网关实际环境填写。

server {
    listen 443 ssl;
    server_name PUBLIC_DOMAIN;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://SERVER_IP:3510;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port 443;
    }
}

可选地在外层网关增加 HTTP 到 HTTPS 的跳转；这属于外层网关的端口与证书策略，不改变 RADAR 服务器的 3510 单端口限制。

无需修改的项：KKFILEVIEW_BASE_URL、KKFILEVIEW_ALLOWED_ORIGINS、ATTACHMENT_PREVIEW_SOURCE_BASE_URL 以及系统设置中的预览地址均可保持原值。当前 RADAR 仅从该地址取受控的 /preview 路径，最终返回给浏览器的是相对路径。

安全加强：仅信任固定外层网关

若 3510 同时允许客户端直接访问，建议用下面两段替换第 8.0 节的简单 map。将 EDGE_NGINX_IP 替换为外层网关连接到 RADAR 服务器时使用的固定源 IP；不要同时保留两套 map。

geo $trusted_preview_gateway {
    default       0;
    EDGE_NGINX_IP 1;
}

map "$trusted_preview_gateway:$http_x_forwarded_proto" $preview_scheme {
    default       $scheme;
    "~^1:https$"  https;
}
双入口共存时保持现状：RADAR 的 CSP_UPGRADE_INSECURE_REQUESTS=false 和 HSTS_ENABLED=false 不要改为 true，否则直接使用 IP/HTTP 的客户端可能被浏览器强制升级到不存在的 HTTPS。若未来彻底停用 IP/HTTP，可只在外层 HTTPS 网关启用 HSTS。

9. 在 RADAR 系统设置确认交付件预览

环境变量生效后，使用具备系统设置权限的账号进入 系统设置 → 基础配置 → 交付件预览：

  1. 打开“交付件预览”开关。
  2. 确认 kkFileView 地址显示为 http://SERVER_IP:3510/preview。
  3. 保存后重新进入需求、工单、开发、测试或投产页面，验证交付件卡片出现预览按钮。

历史版本的预览按钮也会跟随该开关；关闭开关时，当前版本和历史版本均不显示预览动作。

12. 备份、升级与回退

备份

升级 RADAR 镜像前，停止写入或安排维护窗口，并备份宿主机的持久化目录。SQLite 文件与附件目录都必须保留；仅重建容器不能替代数据备份。

cd /opt/radar-offline/radar
docker compose -f compose.yaml ps

# 在运维批准的备份位置创建带日期的副本；以下仅为示例目录名。
mkdir -p /opt/radar-offline/backup-config-YYYYMMDD
cp -a data /opt/radar-offline/backup-data-YYYYMMDD
cp -a attachments /opt/radar-offline/backup-attachments-YYYYMMDD
cp .env compose.yaml /opt/radar-offline/backup-config-YYYYMMDD/

升级 RADAR 镜像

  1. 导入新的 RADAR tar 前，先用日期标签保留当前镜像，例如 docker tag ghcr.io/2guan/radar:latest ghcr.io/2guan/radar:backup-YYYYMMDD；再导入新 tar。
  2. 备份数据、附件、.env 和 compose.yaml。
  3. Compose 保持 image: ghcr.io/2guan/radar:latest，运行 docker compose -f compose.yaml up -d。
  4. 重复第 10 节所有健康与业务验收。

回退

若新版本启动或验收失败，先停止变更后的 Compose 服务，将 image: 改回前一已验证的本地标签，再重新 up -d。若升级包含数据库变更，按该版本发布说明从升级前备份恢复；不要手工猜测或修改 SQLite 内容。
